# Sigma rules

`ingressd` maps every detection rule to a [Sigma](https://github.com/SigmaHQ/sigma)
document so alerts can be correlated in any Sigma-compatible SIEM.

The canonical rule set is generated by the binary (kept in lock-step with the
engine, so it can never drift):

```bash
# Multi-document YAML for all rules
ingressd sigma > ingressd_rules.yml

# Or from the repo
cargo run --release --bin ingressd -- sigma > ingressd_rules.yml
```

Import (pySigma):

```bash
pip install sigma-cli
sigma-convert --backend splunk    ingressd_rules.yml -o splunk_rules.xml   # Splunk
sigma-convert --backend elasticsearch --backend-options ecs-version=8.0 \
      ingressd_rules.yml -o elk_rules.yml                                  # Elastic
sigma-convert --backend loki      ingressd_rules.yml -o loki_rules.yml     # Grafana Loki
```

The alert log source is `product: ingressd`, `service: alerts`; each rule selects
on the `rule` field. Add custom rules via `[[rules.signature]]` (they emit with
`rule: custom-signature` and the signature name in `detail`), and correlate them
with the `ingressd.<rule>` Sigma tag plus the alert's `tags`, `mitre`, and
`risk_score` (0-100) fields.
